## 0. 用語（初学者向け）

| 用語 | かみくだいた意味 |
|---|---|
| PHP | WordPressが動いている土台のプログラム言語。古いと穴が放置される |
| EOL（サポート終了） | 作り手が修理をやめた状態。穴が見つかっても直らない |
| 脆弱性（ぜいじゃくせい） | プログラムの「鍵のかかっていない窓」 |
| RCE | 外部の人が自由にプログラムを動かせてしまう最悪の状態 |
| nonce（ノンス） | 「この操作は本人が押した」と証明する使い捨ての合い札 |
| サニタイズ / エスケープ | 入力された文字を無害化すること |
| WAF | サイトの前に置く門番。怪しい通信を手前で弾く |
| ステージング | 本番と同じ内容のテスト用サイト。ここで先に試す |

## 2. PHPの脆弱性 主要10分類（WordPressで実際に狙われる型）

| # | 分類 | かみくだくと | 典型的な原因コード | 影響 |
|---|---|---|---|---|
| 1 | 任意ファイルアップロード | 画像の代わりにプログラムを置かれる | `move_uploaded_file()` の拡張子未検証 | RCE（最悪） |
| 2 | 権限チェック漏れ | 一般利用者が管理者操作を実行できる | `current_user_can()` 未呼び出し | 権限昇格 |
| 3 | nonce検証漏れ（CSRF） | 他サイト経由で管理操作をさせられる | `check_admin_referer()` 未使用 | 設定改ざん |
| 4 | SQLインジェクション | データベースを直接のぞかれる/壊される | `$wpdb->query("... $_GET[id]")` | 情報漏えい |
| 5 | PHPオブジェクトインジェクション | 保存データを細工して内部処理を乗っ取る | `unserialize($_POST[...])` | RCE |
| 6 | ファイルインクルード（LFI/RFI） | 任意のファイルを読み込ませる | `include $_GET['page']` | 情報漏えい/RCE |
| 7 | XSS | 利用者のブラウザで悪質スクリプトが動く | `echo $_GET[...]`（エスケープなし） | なりすまし |
| 8 | 未認証REST/AJAX | ログイン不要の裏口が開いている | `wp_ajax_nopriv_*` の乱用 | 任意操作 |
| 9 | SSRF | サーバを踏み台に社内側へ通信される | `wp_remote_get($_POST['url'])` | 内部侵入 |
| 10 | 機密ファイル露出 | 設定ファイルが丸見え | `wp-config.php.bak` 等の放置 | DB認証情報漏えい |

### 露出確認（ブラウザのアドレス欄に入れて 404 になるのが正常）


## 3. 対策 10パターン（優先度順）

| 優先 | 施策 | 内容 | 想定コスト | 効果 |
|---|---|---|---|---|
| ★★★ | 1. PHPを8.3/8.4へ更新 | サーバ管理画面でPHP切替。先にステージングで検証 | 低（1〜2h） | 既知の穴を一括で塞ぐ |
| ★★★ | 2. 本体・テーマ・プラグイン全更新 | バックアップ取得 → 更新 → 表示確認 | 低（1h） | 実被害の9割はここ |
| ★★★ | 3. 未使用テーマ/プラグインを削除 | 停止ではなく削除。親テーマ+使用中のみ残す | 低（30分） | 攻撃対象面を縮小 |
| ★★★ | 4. 管理画面の多要素認証（MFA） | ワンタイムコードを必須化 | 低（1h） | ID/PW流出でも守れる |
| ★★☆ | 5. 自動バックアップ＋復旧テスト | 日次・世代管理・サーバ外保管。**復旧を1回必ず試す** | 中（半日） | 被害ゼロ復旧が可能に |
| ★★☆ | 6. WAF導入 | サーバ提供WAF or Cloudflare | 低〜中 | 未知の攻撃も手前で弾く |
| ★★☆ | 7. ログイン防御 | ログインURL変更・試行回数制限・XML-RPC停止 | 低（1h） | 総当たりを遮断 |
| ★★☆ | 8. 権限の最小化 | 管理者を1〜2名に。他は編集者。退職者は即削除 | 低（30分） | 事故の影響範囲を限定 |
| ★☆☆ | 9. 設定の硬化 | ファイル編集禁止、uploads内PHP実行禁止、露出ファイル削除 | 中（2〜3h） | 侵入後の被害を抑制 |
| ★☆☆ | 10. 月次点検の定例化 | 本チェックリストで毎月1回・15分 | 低（継続） | 再発防止 |

### 9の具体設定（サーバ担当者へそのまま渡せる内容）

`wp-config.php` に追記:

```php
define( 'DISALLOW_FILE_EDIT', true );   // 管理画面からのPHP編集を禁止
define( 'WP_DEBUG', false );            // エラー内容を外部に見せない
define( 'WP_DEBUG_DISPLAY', false );
```

`wp-content/uploads/.htaccess`（Apacheの場合）:

```apache
<FilesMatch "\.(php|php5|phtml|phar)$">
    Require all denied
</FilesMatch>
```
